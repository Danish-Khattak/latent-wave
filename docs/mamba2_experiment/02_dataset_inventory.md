## Preprocessing and split audit

- Every configured pretraining key is a precomputed `(N,C,224,224)` float tensor. The current loader simply reads it, casts to float32, and does not resize, convert to dB, or compute normalization statistics. `nrpos-indoor` is stored float64 and is downcast at load time.
- The new trainer makes its unlabeled train/validation split over these already-normalized caches and does not recompute their source-level means or standard deviations. HDF5 attributes record some transform/statistic values, but do not establish that upstream cache normalization was fit on only the later training partition. This inherited fit-scope cannot be verified from the available metadata. By contrast, downstream feature `StandardScaler` instances are fit only on each training split.
- Spectrogram caches already carry transformed values. RFP stores original complex IQ and log/dB-like spectrogram values; the private spectrogram cache records its log/clipping/normalization transform explicitly. Neither configured input should be converted a second time. The CSI caches are real scalar data and already normalized; their source metadata does not support a further magnitude/power conversion.
- Existing pretraining does not use labels from the configured RFP HDF5 file because it loads only `normalized_spectrograms`. The new experiment should likewise consume only the configured sample tensors.
- Existing downstream probe code uses training-only `StandardScaler` through a pipeline. RF/beam/LoS classification uses logistic regression and balanced accuracy (equivalent to mean per-class accuracy on classes represented in the test split). Positioning uses linear regression and de-normalizes with the recorded nominal coordinate range before Euclidean error. Existing classification evaluation averages metrics over seeds 0, 1, and 2; positioning uses only seed 0.
- Existing downstream splits are sample-level. DeepMIMO samples from each scenario can appear on both sides of a random split, so scenario-specific generalization is not measured. The outdoor and RFS caches expose unique per-sample `source_file` values, not repeated group identifiers. Keep the published sample-level split for the primary comparison, save the exact split indices once, and share them across ViT/Mamba. A scenario-held-out DeepMIMO analysis can be reported separately if desired; it must not replace the primary protocol silently.

## Inventory limitations

The caches do not expose raw provenance for `5g-csi.h5`, indoor CSI, or WiFi CSI beyond dataset names and a few summary attrs. Their nonnegative real CSI values are consistent with magnitude-like inputs but cannot be conclusively distinguished from power or another scalar preprocessing from this metadata alone. Full numeric scans verified finiteness, not semantic correctness or source independence.
